# 复刻参考站动态背景：提示词与验收手册

目标参考站：<https://bistutzyy.github.io>（仓库只含生成产物：Hexo 7.3.0 + Butterfly 5.5.4）。
本文记录本站对齐它的完整方法论、实测参数和可复用提示词，便于以后升级主题或换站时复现。

## 0. 结论先行

参考站的"动态背景"**不是手写 canvas**，而是 Butterfly 主题内置的 5 个背景/交互特效，
脚本来自 `butterfly-extsrc@1.1.6`（由主题自动注入）。早期本站用自研 canvas 近似实现，
参数模型与脚本来源都不同，所以怎么调都不像；换成主题内置特效后，视觉效果与参考站同源。

经验：**不要向 AI 描述"做一个炫酷的动态背景"，要直接指定"开启主题的哪些配置块、参数是多少、如何验收"。**

## 1. 参考站实测规格（提取自渲染后的 HTML/CSS）

脚本来源（主题 `plugins.yml` + `cdn.js` 组装，参考站用 jsdelivr）：

- `https://cdn.jsdelivr.net/npm/butterfly-extsrc@1.1.6/dist/canvas-nest.min.js`
- `https://cdn.jsdelivr.net/npm/butterfly-extsrc@1.1.6/dist/canvas-ribbon.min.js`
- `https://cdn.jsdelivr.net/npm/butterfly-extsrc@1.1.6/dist/canvas-fluttering-ribbon.min.js`
- `https://cdn.jsdelivr.net/npm/butterfly-extsrc@1.1.6/dist/fireworks.min.js`
- `https://cdn.jsdelivr.net/npm/butterfly-extsrc@1.1.6/dist/activate-power-mode.min.js`

参考站渲染出的参数（Butterfly 5.5.4；本站 5.7.0 的配置键名以其 `_config.yml` 为准）：

| 特效 | 配置块（5.7.0 键名） | 参考站参数 | 本站取值 |
|---|---|---|---|
| 蛛网连线 | `canvas_nest` | `color: '0,0,255'` `opacity: 0.7` `zIndex: -1` `count: 99` `mobile: true` | 同左，`mobile: false` |
| 鼠标彩带 | `canvas_ribbon` | `size: 150` `alpha: 0.6` `zIndex: -1` `click_to_change: false` `mobile: true` | 同左，`mobile: false` |
| 飘带 | `canvas_fluttering_ribbon` | `enable: true` `mobile: true` | 同左，`mobile: false` |
| 点击烟花 | `fireworks` | `enable: true` `zIndex: 9999` `mobile: true` | 同左，`mobile: false` |
| 打字特效 | `activate_power_mode` | `colorful: true` `shake: true` `mobile: true` | 同左，`mobile: false` |

主题自带的配套 CSS（无需手写）：

- 所有 canvas 与背景层 4s 淡入：`to_show` / `ribbon_to_show` 动画；
- 烟花画布：`position: fixed; z-index: 9999; pointer-events: none`；
- 深色模式在 `#web_bg:before` 叠 `rgba(0,0,0,0.7)` 遮罩；
- 整屏 banner 视差：`background-attachment: fixed`。

两个易错点：

1. `canvas_ribbon` 在配置文件里的键名是 **`click_to_change`**；`data-click` 只是它渲染到 `<script>` 标签上的 DOM 属性名；
2. `mobile` 的判定是**UA 正则**（Android/iOS 等），不是视口宽度。桌面浏览器缩到 390px 宽仍会运行特效，只有移动端 UA 才停用。测试移动端行为必须模拟移动 UA。

## 2. 本站实现方式（已落地并验证）

- 依赖：`hexo-butterfly-extjs@1.5.8`（内含 `butterfly-extsrc@1.1.6`，与参考站同版本）；
- CDN 配置：`third_party_provider: local`，脚本构建期生成到 `dist/pluginsSrc/butterfly-extsrc/dist/`，运行不依赖外部 CDN；
- 自研 canvas 与左下角"动效开关"已移除；首页 Hero 文案注入（kicker/快捷链接/feed 标题）不是背景特效，保留于 `source/js/hero.js`；
- 移动端 `mobile: false` 为有意取舍：手机上不运行画布，桌面端与参考站一致。

代价说明（客观记录）：`local` 会把 `plugins.yml` 里全部第三方脚本写入 `dist`，本站构建产物约 **53 MB**（其中 `pluginsSrc/` 52 个文件）。
若在意体积，可改用替代方案：保留 `third_party_provider: jsdelivr`，仅把 5 个特效脚本在 `tools/prepare.mjs` 中 vendor 到站内并用 `CDN.option` 覆盖路径。

## 3. 可复用提示词模板

以下模板可直接粘贴给 Codex/其他 agent，替换 `<...>` 占位符即可。

### P0 审计（新会话第一条，只读）

```text
项目：<仓库路径>（Hexo <版本> + Butterfly <版本>，包管理器 <pnpm/npm>）。
目标：把动态背景对齐参考站 <参考站 URL>。
本轮只读审计，不改代码，输出《对齐规格表》后等我确认：
1. 读 node_modules/hexo-theme-butterfly/_config.yml，核对 canvas_nest / canvas_ribbon /
   canvas_fluttering_ribbon / fireworks / activate_power_mode 的键名与默认值（以本地版本为准，禁止臆造 key）。
2. 读 _config.butterfly.yml，列出以上配置块是否存在及当前值；定位 inject 与 CDN 段。
3. curl 参考站首页 HTML，搜索 canvas、ribbon、fireworks、powermode、butterfly-extsrc，
   逐条提取真实 script 标签与参数（color/opacity/zIndex/count/size/alpha/mobile/data-click）。
4. curl 参考站 css/index.css，搜索 to_show、ribbon_to_show、#web_bg、fireworks、
   background-attachment，列出背景相关 CSS 规则。
5. 输出表格：效果 / 参考站参数 / 我当前状态 / 需改的文件与 key / 验收标准（可执行的检查命令）。
```

### P1 实施单项（一次只做一个效果）

```text
按已确认规格表实施，硬性规则：
1. 只允许修改 <配置文件与脚本白名单>，禁止修改 themes/ 或 node_modules/ 内文件；
   配置项不存在时直接报告（说明主题版本原因），禁止自创 key 或用 JS hack。
2. 本次只做 <特效名>，参数：<从规格表粘贴>。
3. 改完必须执行 <构建命令>，然后在生成产物中 grep 出对应 script 标签并贴原始输出作为证据。
4. 完成后停手等我验收，不要顺手做其他效果。
```

### P2 脚本本地托管（可选）

```text
目标：特效脚本改为站内托管，不依赖外部 CDN。
1. 安装 hexo-butterfly-extjs（版本需与主题匹配）。
2. 将 CDN.third_party_provider 改为 local；保留其他 option 覆盖不动。
3. 构建后确认 script 的 src 以 /<站点根>/pluginsSrc/ 开头，且对应文件存在于产物目录。
4. 报告构建产物体积变化；说明 local 会打包全部第三方脚本这一副作用。
```

### P3 测试重写（让 CI 能验收视觉行为）

```text
把浏览器测试中断言自研特效的部分，改为断言主题内置特效：
1. 桌面视口：背景层 canvas 数量 = <N>（canvas_nest/ribbon/fluttering），烟花 canvas 存在；
   对背景层 canvas 的 toDataURL 采样两次，断言内容随时间变化（证明在动画）。
2. 移动端：新建带 iPhone UA 的页面（UA 判定，不是视口宽度），断言背景 canvas 数量为 0；
   烟花为静态 canvas（无 mobile 限制的静态元素可保留）。
3. 断言 5 个特效脚本均从站内路径加载。
4. 保留原有布局/搜索/画廊/明暗主题断言；不得引入 pageerror。
```

### P4 排障（特效没生效时）

```text
现象：<具体现象>。按顺序排查，每步只做一个假设并给证据：
1. YAML 解析结果中对应配置块的值；
2. 生成产物中是否出现对应 script 标签；若没有，去 theme 的 effect.pug 找注入条件；
3. script 的最终 URL 在产物目录中是否存在（对照主题 scripts/events/cdn.js 的拼接逻辑）；
4. 浏览器控制台报错、canvas 是否存在、是否被遮挡（给出 DevTools 片段）；
5. 只修最可能的一个原因，改完给出验证命令。
```

### P5 验收报告

```text
输出验收报告，每项给"通过/不通过 + 证据"：
- 桌面与移动端（移动 UA）的实际 canvas 数量与动画状态；
- light/dark 两种模式下特效与遮罩表现；
- 5 个脚本的注入参数与站内路径；
- 构建与浏览器测试命令的原始输出；
- 与参考站的有意差异清单（例如本项目的 mobile: false）。
```

## 4. 验收清单

```powershell
# 1. 构建 + 站内链接与特效标记校验（tools/verify.mjs）
pnpm build

# 2. 浏览器回归（布局、搜索、画廊、明暗主题、桌面/移动 canvas 断言）
pnpm test:browser

# 3. 手工提取注入证据（在产物目录执行）
node -e "const h=require('fs').readFileSync('dist/index.html','utf8');console.log(h.match(/<(?:script|canvas)[^>]*(?:canvas_nest|ribbon|fireworks|activate-power-mode)[^>]*>/g).join('\n'))"
```

预期：5 个 script 标签参数与规格表一致；桌面 5 个 canvas（3 个背景层 z-index -1 + 烟花 + 打字粒子）、移动 UA 下仅静态烟花 canvas；无控制台错误。

## 5. 差异与取舍记录（本站）

| 项 | 参考站 | 本站 | 原因 |
|---|---|---|---|
| 移动端 canvas | 全部运行 | 全部停用（`mobile: false`） | 手机性能与流量 |
| 左下角动效开关 | 无 | 已移除 | 与参考站 1:1 |
| 首页 Hero 文案/快捷链接 | 不同设计 | 保留本站设计（`source/js/hero.js`） | 属于本站原创风格，不属于背景特效 |
| 脚本来源 | jsdelivr CDN | 站内 `pluginsSrc/` | 运行不依赖外部 CDN |
| 背景底色 | — | `#f9fbfd`（深色模式另有底色） | 本站既有设计 |
